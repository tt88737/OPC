# OPC 底座清理与加固设计

## 目标

将当前可运行的 OPC 工程整理为可从 Git 完整克隆、可重复构建、默认安全、无 RuoYi 工程残留、具备健康检查、自动化测试和 CI 验证的标准底座。

## 范围

本次工作按以下顺序实施：

1. 完成 Git 文件纳管和前端锁文件管理。
2. 删除默认密码、测试账号及 RuoYi 示例代码和数据。
3. 拆分开发与生产安全配置。
4. 增加标准健康检查。
5. 增加自动化测试与 GitHub Actions CI。

不在本次范围内：新增业务模块、调整现有权限模型、重做前端视觉设计、引入数据库迁移框架、调整线上基础设施。

## Git 与可重复构建

- 纳管所有后端源码、前端源码、SQL、运行脚本、项目文档和必要配置。
- 纳管 `frontend/package-lock.json`，CI 使用 `npm ci` 安装锁定依赖。
- 忽略本地密钥文件、日志、构建产物、IDE 文件、`node_modules` 和前端 `dist`。
- 删除或忽略依赖树文本、临时诊断文件和本地控制台备份等非交付产物。
- 提交前验证 `git status` 中没有应纳管源码处于未跟踪状态。

## 安全初始化

### 初始化管理员

- 初始化 SQL 保留用户编号为 `1` 的 `admin` 账号，以维持现有角色、岗位和部门关联。
- 初始化账号默认禁用，密码字段使用不可登录的占位哈希，不包含任何公开默认密码。
- 首次启动通过 `OPC_BOOTSTRAP_ADMIN_PASSWORD` 提供管理员密码。
- 引导逻辑只在管理员处于明确的“未初始化”状态时运行。
- 密码必须通过现有密码强度规则，并以 BCrypt 保存。
- 初始化成功后启用管理员账号；后续启动不得再次覆盖密码。
- 环境变量缺失时应用仍可启动，但管理员保持禁用，日志只输出不含秘密的操作提示。
- 环境变量内容不得写入日志、数据库备注或异常消息。

### 删除默认数据和示例代码

- 删除 `ry` 测试用户及其角色、岗位关联。
- 删除 `RyTask`、`ryTask` Bean、三条示例定时任务及相关界面示例文字。
- 删除 Swagger `TestController` 和其中的内存用户、明文密码。
- 清理启动脚本、路由示例、注释、页脚年份中的旧命名或年份残留。
- 初始化 SQL 和当前本地数据库同步清理，避免源码与验证环境结论不一致。

## 环境配置

### 通用配置

`application.yml` 只保留端口、上传限制、MyBatis、分页等环境无关配置，并通过 `OPC_PROFILE` 选择运行环境。数据库、Redis、JWT 等秘密继续由环境变量注入。

### 开发配置

`application-dev.yml` 面向本地开发：

- 可显式开启 Swagger UI 和 Druid 控制台。
- 访问范围限制为本机或配置的开发来源。
- 不提供 Druid 固定用户名和密码；开启控制台时必须通过环境变量注入。
- 支持本地数据库与 Redis 配置，但示例文件不包含真实秘密。

### 生产配置

`application-prod.yml` 默认安全：

- Swagger UI、OpenAPI 文档和 Druid 控制台默认关闭。
- DevTools、详细错误信息和调试日志关闭。
- CORS 只接受明确配置的来源，不提供宽泛生产默认值。
- JWT、数据库和需要认证的 Redis 配置缺失时启动失败。
- 不提供任何管理入口的默认凭据。

## 健康检查

- 引入 Spring Boot Actuator。
- 匿名公开且只公开 `/actuator/health`。
- 健康响应检查应用、数据库和 Redis 状态。
- 默认不公开环境、Bean、配置属性、线程等敏感端点。
- 生产环境健康响应不展示组件内部细节，只返回总体状态。

## 自动化测试

### 后端

- 管理员未初始化且未提供密码时保持禁用。
- 提供合格密码时完成 BCrypt 初始化并启用账号。
- 已初始化账号不会被环境变量重复覆盖。
- 弱密码被拒绝且不会泄露密码内容。
- 生产配置默认关闭 Swagger 和 Druid。
- `/actuator/health` 可匿名访问，其他业务接口仍需认证。
- 初始化 SQL 不包含 `admin123`、`123456`、`ryTask`、测试用户 `ry`。

### 前端与仓库

- `package-lock.json` 必须存在并被 Git 纳管。
- `npm ci` 和生产构建必须成功。
- RuoYi 工程残留扫描必须通过。
- 现有 Swagger 中文注解检查继续执行。

## CI

GitHub Actions 在推送和拉取请求时执行：

1. 使用 Java 17 和 Maven 运行后端测试及打包。
2. 使用锁文件执行 `npm ci` 和前端生产构建。
3. 执行 Swagger 注解检查和 RuoYi 残留检查。
4. 执行 `npm audit`。
5. 独立执行 OWASP Dependency-Check，并上传扫描报告；外部漏洞源不可用时明确标记扫描不完整，不伪装为零漏洞。

## 许可证合规

- 产品名称、界面、包名和业务文案统一使用 OPC。
- 根目录与前端许可证继续声明 OPC 自有部分。
- 新增 `THIRD_PARTY_NOTICES.md`，保留上游 MIT 项目的必要版权和许可证声明。
- 第三方声明不作为产品品牌展示，也不恢复已删除的菜单或推广信息。

## 错误处理与回滚

- 引导密码校验失败只阻止管理员初始化，不修改原账号状态。
- 配置缺失应在启动阶段给出明确的变量名称，但不输出变量值。
- 每阶段独立提交并运行对应验证；出现回归时可按阶段回退。
- 修改当前本地数据库前先导出涉及的用户、关联和任务记录，确保可恢复。

## 验收标准

- 全新克隆包含完整工程，`git status` 不存在遗漏源码。
- 后端测试、打包和前端 `npm ci`、生产构建全部成功。
- 初始化 SQL、源码和当前数据库均无公开默认密码及 RuoYi 示例数据。
- 管理员只能通过一次性环境变量完成首次初始化，且不会被重复覆盖。
- 生产配置默认关闭 Swagger、Druid 和开发工具。
- `/actuator/health` 返回标准健康状态，业务鉴权边界不被放宽。
- CI 覆盖构建、测试、残留检查和依赖漏洞检查。
- 许可证文件和第三方声明满足 MIT 通知保留要求。
