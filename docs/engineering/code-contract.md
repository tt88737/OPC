# OPC 代码规范契约

## 1. 目的与效力

本契约定义 OPC 底座新增和修改代码的最低质量标准。文中的“必须”是合并门禁，“应当”如需偏离必须在 PR 中解释，“建议”用于持续改善。历史代码不要求一次性重写，但任何变更不得扩大技术债。

## 2. 技术与编码基线

| 范围 | 契约 |
| --- | --- |
| Java | Java 21；UTF-8；通过仓库 Checkstyle；优先使用清晰的领域命名，不使用无意义缩写 |
| 后端 | Spring Boot 4、Spring Security、MyBatis；构造器注入优先；事务边界放在服务层 |
| 前端 | Vue 3、Vite、Element Plus、Pinia；通过 ESLint 与 Prettier；组件保持单一职责 |
| 构建 | 只使用 `mvnw.cmd`/`mvnw` 和锁定的 `package-lock.json`；禁止提交本地依赖缓存和构建产物 |
| 配置 | 环境差异通过 profile 和环境变量表达；仓库只保存安全默认值和占位示例 |

## 3. 模块边界

- `opc-admin`：启动入口、Web 接口装配和应用配置，不承载可复用业务规则。
- `opc-framework`：安全、Web、数据源、缓存等框架能力，不依赖具体业务页面。
- `opc-system`：系统管理领域、Mapper、Service 及业务模型。
- `opc-common`：稳定且跨模块复用的基础类型和工具；不得成为任意代码的堆放区。
- `opc-quartz`、`opc-generator`：分别只处理任务调度和代码生成职责。
- `frontend/src/api` 管理请求契约，`store` 管理跨页面状态，`views` 负责页面编排，`components` 承载可复用交互。

跨模块调用必须面向公开服务或清晰接口，不得绕过服务层直接访问其他模块的 Mapper。新增公共抽象前，必须存在真实复用或明确的稳定边界。

## 4. 后端规则

### 4.1 API 与校验

- Controller 只负责协议转换、参数校验、授权声明和结果返回；业务判断进入 Service。
- 外部输入必须使用 Bean Validation 或等价的显式校验；不得信任前端校验。
- 新增或修改接口必须维护 OpenAPI 中文说明、请求/响应模型和错误语义。
- HTTP 方法、状态码和幂等语义必须匹配行为；批量、删除、导入等操作必须定义部分失败策略。
- 禁止直接向客户端返回堆栈、SQL、内部路径或敏感字段。

### 4.2 领域、持久化与事务

- Entity/DO、DTO、查询对象和展示对象职责应清晰，跨边界时不得无审查地复用数据库实体。
- SQL 必须参数化；动态排序字段、表名等不能参数化的内容必须使用白名单。
- Service 层定义事务；事务中不得执行不可控的长耗时远程调用。
- 数据库变更脚本必须可审查、可重复部署并有回滚或前向修复方案；禁止启动时静默修改生产结构。
- 列表查询必须考虑分页、索引和 N+1；高频路径的慢 SQL 需要执行计划证据。

### 4.3 异常、日志与安全

- 使用统一异常处理；禁止空 `catch`、仅 `printStackTrace` 或吞掉错误后返回成功。
- 日志按 `ERROR/WARN/INFO/DEBUG` 语义记录；正常生产流程不得输出 DEBUG SQL。
- 日志参数化输出，不拼接大对象；密码、Token、验证码、数据库凭据和个人敏感信息必须脱敏或不记录。
- 权限检查必须在服务端完成；新增资源同时检查认证、授权、数据范围和越权访问。
- 随机密钥使用安全随机源；禁止硬编码秘密或在测试中使用真实秘密。

## 5. 前端规则

- 页面组件负责组合，不得复制 `src/api` 已有请求、权限或错误处理逻辑。
- 表单必须包含提交中、成功、失败、空数据和校验状态；重复提交应被禁用或具备幂等保障。
- 所有异步请求必须处理失败和结束状态，不能让 loading 永久悬挂。
- 权限指令只改善界面体验，不能替代后端授权。
- 组件 props、emits 和双向绑定必须有清晰契约；禁止直接修改 props。
- 新增交互必须兼顾键盘操作、焦点、可读标签、窄屏文本溢出和浏览器控制台错误。
- 依赖版本变更必须说明用途、安全影响和包体影响，不得顺带大范围升级。

## 6. 测试契约

| 变更类型 | 最低验证 |
| --- | --- |
| 纯文档 | 链接、命令和术语人工校验；适用时运行文档契约测试 |
| Java 工具/服务 | 单元测试覆盖正常、边界和失败路径；运行目标模块测试 |
| Controller/API | 参数校验、权限、成功和错误响应测试；必要时集成测试 |
| Mapper/SQL | 数据集成测试或可重复 SQL 验证，覆盖空值、分页和边界数据 |
| Vue 逻辑 | Node 单测；页面变更补充关键状态验证 |
| 用户流程 | 前后端联调；验证加载、成功、失败、权限和刷新后的状态 |
| 安全/配置 | 对应 profile/安全脚本和完整门禁 |

测试必须可重复、互相隔离，不依赖执行顺序或真实生产数据。修复缺陷应保留回归测试。新增代码不能依赖当前 5% 覆盖率基线作为免测理由。

## 7. 完成定义

一项代码变更只有同时满足以下条件才算完成：行为符合验收标准；相关测试通过；无新增敏感信息和高风险告警；文档、配置示例、API 契约与实现一致；数据库和兼容性影响已说明；完整验证通过，或已如实记录无法执行的项目与风险。
