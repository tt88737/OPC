# OPC 新功能契约清单

每个新增或修改功能在进入 `Build` 前填写本清单。它是需求、PR 和 Codex 交付说明的共同入口；不适用项必须写明原因，不能留空。

## 需求与范围

- [ ] 用户、问题、目标和非目标已明确。
- [ ] 验收标准可观察、可测试，包含成功、失败、空状态和权限场景。
- [ ] 风险等级为 L1/L2/L3，并说明判断理由。
- [ ] 变更范围、负责人、依赖和回滚方向已记录。

## API 与权限

- [ ] API 类别为 C 端、B 端、内部或运维，并明确调用方。
- [ ] 每个管理接口有服务端 `@PreAuthorize`；前端 `v-hasPermi` 仅作为界面体验。
- [ ] 权限字符串、菜单数据、路由权限和数据范围语义一致。
- [ ] 输入校验、错误码、幂等、分页、排序和兼容性已说明。
- [ ] Controller 有中文 `@Tag`/`@Operation`/参数和响应 OpenAPI 说明。

## 审计与安全

- [ ] 新增、修改、删除、导入、导出、授权、强退、配置和文件操作已判断是否需要 `@Log`。
- [ ] 审计记录包含操作者、时间、来源、结果和必要的目标/前后值；敏感字段已脱敏。
- [ ] 认证、授权、数据范围、越权、重放、限流和文件安全已检查（适用时）。
- [ ] 未引入密码、令牌、私钥、生产连接串或未脱敏个人数据。

## 数据与运行

- [ ] 数据所有权、表/字段、索引、审计字段和缓存一致性已确定。
- [ ] 数据库脚本已版本化、幂等，并有前向修复或回滚方案；破坏性操作有明确授权。
- [ ] 配置项有安全默认值、环境变量示例和 profile 行为。
- [ ] 日志、指标、健康检查、容量和降级影响已说明（适用时）。

## 验证与交付

- [ ] 已先补复现测试或说明为什么无法自动化。
- [ ] 已运行目标模块测试、静态检查和 `verify-api-contracts.ps1`。
- [ ] UI 变更已检查桌面/窄屏、加载/失败/权限状态和浏览器控制台。
- [ ] 已运行完整 `bin/verify-foundation.ps1`，或记录原始失败原因和残余风险。
- [ ] PR 已写明行为变化、配置/数据库影响、验证结果、发布观察和回滚命令。
